# eNatura Social Preview 1.0.0

Отдельный плагин WordPress 6.6+, PHP 7.4+ (для эксплуатации используйте поддерживаемый PHP). Не зависит от темы и WooCommerce. GPL-2.0-or-later.

## Установка

1. Сохраните резервную копию и проверьте плагин на тестовой копии сайта.
2. «Плагины → Добавить плагин → Загрузить» → `enatura-social-preview-1.0.0.zip` → активировать.
3. «Настройки → eNatura Social Preview»: оставьте автоматический режим. Загрузите в медиатеку утверждённую картинку бренда (рекомендуем JPEG/PNG 1200×630, до 5 МБ), укажите её ID из URL редактирования `post=123`. Настройка не требует URL домена. 0 отключает резервную картинку. Убедитесь, что медиа не прикреплено к закрытой записи.
4. Проверьте название, краткое описание и язык в настройках WordPress; назначенную главную страницу — в «Чтение». У страниц/записей задайте excerpt и изображение записи, у товара — краткое описание и основное изображение.
5. Очистите HTML-кеш WordPress, сервера и CDN. Для multisite активируйте/настраивайте на каждом сайте отдельно.

В комплект намеренно не включены картинки темы, иконка сайта и неутверждённые макеты продукции. Без выбранной картинки и изображения материала теги изображения отсутствуют. Это честный fallback, но визуальная карточка будет неполной.

## Откуда берутся данные

Все теги выводятся сервером в `wp_head`, без JavaScript и внешних запросов. `og:url` использует WordPress canonical для singular, ссылки WordPress для главной/ленты, таксономий и архивов типов записей. Пагинация учитывается. Плагин не добавляет второй HTML `rel=canonical`; им продолжает управлять WordPress/SEO-плагин.

Главная: название сайта, его описание; если описание пустое — excerpt/очищенное содержимое назначенной главной страницы. Изображение — её featured image, затем бренд. Для записей/страниц: заголовок, excerpt → очищенное содержимое → описание сайта. Шорткоды не исполняются, HTML/скрипты/комментарии удаляются, описание ограничено 200 символами. Заголовок без текста заменяется названием сайта. Если исходные поля пусты, плагин не придумывает описание.

Товары при наличии WooCommerce: настоящее название, краткое → полное описание, основное изображение. Без WooCommerce обычный публичный тип записи работает без фатальных ошибок. Товар выводится как стандартный `website`: цены, доставка, наличие, Product Schema и медицинские обещания не добавляются. Страница магазина обрабатывается как архив, а корзина, оформление и аккаунт исключены.

JPEG/PNG/WebP/GIF берутся из медиатеки с реальными размерами и alt. SVG/AVIF не используются для совместимости карточек. Изображения меньше 200×200 не используются; миниатюра шириной менее 600px уступает горизонтальной брендовой картинке от 600px. В остальных случаях приоритет у изображения материала. Для горизонтального изображения от 600×315 выбирается `summary_large_image`, иначе `summary`. Размеры не гарантируют конкретный вид карточки: сервис может кадрировать квадратный товар или выбрать компактный формат. Иконка сайта/логотип не подставляются автоматически. Проверяйте доступность файлов и размер вручную; плагин не скачивает файлы и не проверяет лимит байтов/CDN.

Отключён вывод для непубличного сайта (`blog_public=0`), preview, password-protected (даже после ввода пароля), draft/private, поиска, 404, feeds, embed и неизвестных типов архивов (включая author/date). Дополнительные ограничения доступа членства/платных материалов не определяются автоматически: используйте фильтр `enatura_social_preview_enabled` и исключите их из общего HTML-кеша. `noindex` сам по себе не равен закрытому доступу.

## Совместимость и дубли

Автоматический режим полностью уступает вывод при обнаружении Yoast SEO, Rank Math, All in One SEO, SEOPress, The SEO Framework, Slim SEO, Jetpack Publicize. Существующие теги не отключаются. Даже если карточки отключены в настройках обнаруженного SEO-плагина, eNatura осторожно остаётся в ожидании. Для включения сначала убедитесь по исходному HTML, что другой генератор отсутствует, затем выберите принудительный режим. Отключение своего генератора в другом плагине — отдельное осознанное действие администратора.

Универсального безопасного способа обнаружить уже напечатанные теги неизвестной темы/плагина нет. Проверяйте исходный HTML. Для собственного провайдера используйте `add_filter('enatura_social_preview_external_provider', '__return_true');`. Для запрета на отдельных страницах используйте фильтр `enatura_social_preview_enabled` (boolean, вызывается в wp_head). Фильтры добавляйте в собственный плагин, а не в этот архив. Настройки хранятся в option `enatura_social_preview`; при деактивации сохраняются, при удалении удаляются на обычном сайте. На multisite удалите option отдельно для каждого сайта при необходимости.

## Проверка карточек и кеша

Откройте публичный URL анонимно и «Исходный код страницы». При активном выводе должен быть один набор `og:*` и `twitter:*`, правильные `og:url`, язык, заголовок, description, абсолютный URL изображения, его width/height/alt. `curl -L 'PUBLIC_URL'` должен получать те же теги без выполнения JS. Откройте изображение анонимно: 200 OK, правильный MIME, без авторизации, запрета robots/WAF или защиты hotlink. HTTPS должен работать для страницы и изображения. В теме необходим вызов `wp_head()`.

Проверьте главную, запись с/без картинки/excerpt, длинный/HTML-текст, страницу, товар с/без картинки, магазин, таксономию и вторую страницу архива. Отдельно проверьте password/private/draft/preview, отключённую индексацию, отсутствие WooCommerce, SEO auto/on/off и мобильные клиенты.

Facebook: [Sharing Debugger](https://developers.facebook.com/tools/debug/) и повторный Scrape Again после очистки своего кеша. Telegram, VK, WhatsApp, X: отправьте URL в тестовый личный диалог/черновик и проверьте фактическое отображение; обновление на разных клиентах может различаться. Для VK доступен [метод pages.clearCache](https://dev.vk.com/ru/method/pages.clearCache), требующий подходящего доступа; плагин его не вызывает. Не обещаем немедленный сброс внешнего кеша. После замены картинки предпочтительно загрузить новый медиафайл с новым URL, затем заново запросить карточку. Query-параметр на ссылке не является гарантией обновления, поскольку canonical остаётся тем же. Приватный/staging-сайт недоступен внешним роботам.

## Первичные источники, проверено 27 октября 2026

- [Open Graph protocol](https://ogp.me/): базовые свойства и структурированные размеры/alt изображения.
- [WordPress canonical](https://developer.wordpress.org/reference/functions/wp_get_canonical_url/): опубликованные записи и пагинация; [публичность записи](https://developer.wordpress.org/reference/functions/is_post_publicly_viewable/).
- [WooCommerce WC_Product](https://woocommerce.github.io/code-reference/classes/WC-Product.html): реальные getters описания/основной картинки.
- [Meta image guidance](https://developers.facebook.com/docs/sharing/webmasters/images/): источник вернул 429 при проверке; актуальные численные лимиты не подтверждены этой сессией. 1200×630 — выбранная практическая рекомендация плагина, не гарантия всех сервисов.
- [X large image cards](https://developer.x.com/en/docs/x-for-websites/cards/overview/summary-card-with-large-image) и старый адрес developer.twitter.com при проверке перенаправляли на общий docs.x.com/overview. Актуальные ограничения X не удалось подтвердить по этой странице. Используется стандартная разметка twitter:card/title/description/image/image:alt, без выдуманного twitter:site.

Telegram/VK/WhatsApp самостоятельно решают, отображать ли карточку. Плагин выдаёт общие OG-данные, не обещает одинаковый формат и доступность предпросмотра.

## Проверки реализации

Результаты доступны в `tests/social-preview/RESULTS.md` в рабочем проекте (не в устанавливаемом архиве). Изолированные тесты с заглушками WordPress проверяют контракты, но не заменяют интеграцию с настоящим WordPress, WooCommerce, SEO-плагинами, кешем и внешними роботами. Плагин не устанавливался на живой сайт и не публиковался в репозиторий темы.
